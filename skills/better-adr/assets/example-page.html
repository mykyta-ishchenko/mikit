ADR 2026-10-18

Pushes go straight to Apple, with no service in between

The app needs to say when an analysis or a review is ready and remind people to write. The backend sends every push itself through Apple's push service with one key. OneSignal is dropped before launch.

Nothing private leavesA push carries only its kind and an id. The words live in the app.
Free at any sizeNo monthly user cap and no new processor of personal data.
No push SDK in the appThe app registers its token with our backend, and that's all.

ArchitectureHow it works

The app registers each install with the backend, and a person can have several. When an analysis completes, a review is written or a copy of the data is ready, that news goes through the outbox and starts one Temporal run, so it is told once. A reminder run does the same at the hour each person chose, in their own time zone. The run sends to every device through the APNs adapter, and Apple delivers it. The phone shows the app's own words for that kind of news.

ScopeWhat's in it now, and what comes later

In 1.0

  • News when an analysis, a review or a copy of the data is ready
  • A daily reminder at the hour the person chose, skipped if they already wrote
  • A switch per kind in the profile; a kind that is off arrives silently
  • Every device the person is signed in on
  • An admin switch that stops sending without a deploy

Later, if Android comes

  • Google FCM behind the same sending port
  • Devices already store which push service knows them

Options consideredWhy this option

  • Direct APNsChosen. Apple is the only processor, it costs nothing, and reminders use data the backend already has.
  • OneSignalIts free plan caps push at 1,000 monthly users, and it would hold our devices as another processor.
  • FCM for iOSGoes through APNs anyway and adds Google as a processor.
  • FCM for AndroidRight if an Android app comes. Not before.

ConsequencesWhat it costs

  • Dead tokens are oursApple refuses tokens of reinstalled phones. The device is forgotten unless the app registered it again.
  • One key stops everythingA wrong key fails every push. The worker does not start with a key it cannot sign with.
  • Silent pushes may not arriveApple delays or drops them. The app refreshes when it opens instead.
  • No delivery dashboardWhat happened to a push shows only in logs and Sentry.

Next stepsOne-time setup

Done for 1.0. Repeat only for a new app or a new key.

  1. Create the .p8 key in the Apple Developer account for both push services
  2. Store it as a secret for every environment
  3. List every bundle id that may register devices in the backend config
  4. Restart the workers after adding an app, so Apple ties the connection to it
